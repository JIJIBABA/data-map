# data-map 更新部署流程（手动版）

> 适用场景：代码有更新后，重新部署到 `12.0.216.77`。
> 每次更新按这个流程操作。建议把整个文档从头到尾读一遍再动手。

---

## 前置：在开发机（Windows）准备新产物

每次更新代码后，先在开发机重新构建出新的 jar 和 dist。

### 1.1 重新打包后端（如果后端代码有改动）

打开 cmd / PowerShell，执行：
```bash
cd D:\self\data-map\data-map-backend
mvn clean package -DskipTests
```
产物：`D:\self\data-map\data-map-backend\target\data-map-backend-1.0.0.jar`

- 看到 `BUILD SUCCESS` 就成功
- 看到报错，把报错贴给我，别往下走

### 1.2 重新构建前端（如果前端代码有改动）

```bash
cd D:\self\data-map\data-map-frontend
npx vite build
```
产物：`D:\self\data-map\data-map-frontend\dist\` 目录

- 看到最后的 `✓ built in xxs` 就成功

### 1.3 组装上传包

把新的 jar 和 dist 放到一个目录里打 zip。在开发机执行：
```bash
cd D:\self\data-map
# 准备一个干净的上传目录
rmdir /s /q update-pkg 2>nul
mkdir update-pkg
:: 后端 jar（后端没改也要带上，保持版本一致）
copy data-map-backend\target\data-map-backend-1.0.0.jar update-pkg\
:: 前端 dist（整个目录）
xcopy /e /i data-map-frontend\dist update-pkg\dist
:: 配置文件（一般不用改，但带上保险）
copy docs\application-prod.yml update-pkg\config\ 2>nul
mkdir update-pkg\config 2>nul
copy docs\application-prod.yml update-pkg\config\
:: 打包
powershell Compress-Archive -Path update-pkg\* -DestinationPath update.zip -Force
```
> 上面的命令在 **cmd** 里跑（不是 bash）。

产物：`D:\self\data-map\update.zip`

> **简化判断**：
> - 只改了前端 → 只需要 `dist` 目录，jar 可以不更新（见后面"只更新前端"快路）
> - 只改了后端 → 只需要新的 jar，dist 不用动
> - 都改了 → 两个都更新

## 服务器操作：四步走

登录服务器 `12.0.216.77`（用 scfadmin 账号）。

### 第 1 步：上传新文件

用 **WinSCP / Xftp**（推荐，拖拽上传）把 `update.zip`（或单独的 jar / dist 目录）传到服务器你的家目录 `/home/scfadmin/`。

> 如果只更新一个 jar，直接传 jar 文件就行，不用打 zip。

### 第 2 步：停掉旧进程（重要！）

```bash
# 查看当前在跑的进程，确认一下
ps -ef | grep data-map-backend | grep -v grep

# 停掉它
pkill -f data-map-backend-1.0.0.jar

# 等 2 秒，确认停了
sleep 2
ps -ef | grep data-map-backend | grep -v grep
# 这条应该没有输出，说明停干净了
```

> 如果 `pkill` 后还有输出，说明没杀掉，再跑一次 `pkill -9 -f data-map-backend-1.0.0.jar`

### 第 3 步：替换文件

根据你更新了什么，二选一或都做：

**情况 A：只更新后端（换 jar）**
```bash
# 把新 jar 覆盖到部署目录
cp /home/scfadmin/data-map-backend-1.0.0.jar ~/datamap/backend/
```

**情况 B：只更新前端（换 dist）**
```bash
# 删旧的，换新的
rm -rf ~/datamap/frontend/dist
# 如果上传的是 zip，先解压；如果直接传的 dist 目录，cp 进来
unzip /home/scfadmin/update.zip -d /tmp/update-pkg   # 如果打成了 zip
cp -r /tmp/update-pkg/dist ~/datamap/frontend/dist
```

**情况 C：后端前端都更新**
先做 A 再做 B。

> 配置文件 `~/datamap/config/application-prod.yml` 一般不用动，除非改了数据库连接或端口。

### 第 4 步：启动新进程

```bash
nohup java -jar ~/datamap/backend/data-map-backend-1.0.0.jar \
  --spring.config.additional-location=file:$HOME/datamap/config/ \
  --spring.profiles.active=prod \
  > ~/datamap/backend/backend.log 2>&1 &

# 等待 15 秒让 Spring Boot 启动
sleep 15
```

## 验证（每次更新都要做）

### 1. 看进程在不在
```bash
ps -ef | grep data-map-backend | grep -v grep
```
有进程 → 继续；没有 → 看日志找原因

### 2. 看启动日志（最关键）
```bash
tail -40 ~/datamap/backend/backend.log
```
关注：
- 出现 `Started DataMapApplication in x.xxx seconds` → ✅ 启动成功
- 出现 `Connection refused` / `Communications link failure` → 数据库连不上
- 出现 `Port 8966 was already in use` → 端口被占，旧进程没杀干净，回第 2 步重杀
- 出现 `Error` / `Exception` → 把这段日志贴给我

### 3. 测试接口
```bash
curl -o /dev/null -w "首页 HTTP %{http_code}\n" http://127.0.0.1:8966/
curl -o /dev/null -w "API  HTTP %{http_code}\n" http://127.0.0.1:8966/api/projects
```
两个都返回 `HTTP 200` → ✅ 成功

### 4. 浏览器验证
打开 **http://12.0.216.77:8966/**
- 页面正常、能看到表列表 → ✅ 全部成功
- 改动生效（比如新功能能用）→ ✅✅
- 浏览器显示旧内容 → 按 `Ctrl + Shift + R` 强制刷新清缓存

## 快路：只更新前端（后端不动）

前端更新最简单，**不用停进程、不用重启后端**：

```bash
# 1. 把新的 dist 传到服务器（WinSCP 拖过去）

# 2. 直接替换
rm -rf ~/datamap/frontend/dist
cp -r /home/scfadmin/dist ~/datamap/frontend/dist

# 3. 浏览器 Ctrl+Shift+R 强刷
```
前端是静态文件，后端实时读取，不用重启。刷新就能看到新页面。

## 故障排查

### 启动失败：端口被占
```
Port 8966 was already in use
```
说明旧进程没杀干净：
```bash
# 查谁占着
ss -tlnp | grep :8966
# 或
netstat -tlnp 2>/dev/null | grep :8966
# 杀掉
pkill -9 -f data-map-backend-1.0.0.jar
```

### 启动失败：数据库连不上
```
Communications link failure / Connection refused
```
服务器连不上 MySQL `12.0.221.123:3311`。测一下网络：
```bash
# 测端口通不通
curl -v telnet://12.0.221.123:3316 2>&1 | head -5
# 或
nc -zv 12.0.221.123 3311
```
不通 → 找网络管理员开通，或把数据库迁到本地。

### 启动失败：找不到配置 / classpath 报错
确认文件都在：
```bash
ls -l ~/datamap/backend/data-map-backend-1.0.0.jar
ls -l ~/datamap/config/application-prod.yml
ls ~/datamap/frontend/dist/index.html
```

### 浏览器打不开（部署后）
防火墙没开 8966（需要 sudo）：
```bash
sudo firewall-cmd --add-port=8966/tcp --permanent
sudo firewall-cmd --reload
```

### 看完整日志
```bash
# 看最近 50 行
tail -50 ~/datamap/backend/backend.log
# 实时跟踪
tail -f ~/datamap/backend/backend.log
# 按关键字找报错
grep -i "error\|exception\|fail" ~/datamap/backend/backend.log | tail -20
```
